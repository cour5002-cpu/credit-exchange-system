# 8周任务详细分工规划

## 1. 规划目标

本规划用于指导两个人在 8 周内完成“课时兑换学分系统”V1 的开发、测试、部署和上线准备。

当前分工默认如下：

- 你：整体规划、业务规则、数据库设计、后端开发、权限、部署主导
- 对方：页面结构、前端页面、交互、样式、可视化、静态资源

为了避免返工，整体执行原则如下：

1. 第 1 周冻结 V1 范围，后续原则上不新增核心流程
2. 第 3 周后不再随意改核心表结构
3. 第 6 周起重心从开发转向联调、测试和上线准备
4. 每周结束必须有明确交付物

---

## 2. 第1周：需求冻结 + 设计定稿

### 2.1 你的工作

第 1 周你的工作不是写功能，而是把系统“定义清楚”。建议产出以下内容：

#### 1. V1 范围冻结清单

需要包含：

- V1 必做功能
- V1 延后功能
- 暂不做功能
- 每个模块的边界说明
- 上线验收标准

举例：

- 必做：指导老师前置确认、管理员分配审核老师、审核老师审核、管理员最终确认
- 延后：企业微信登录、统计报表、复杂通知中心
- 不做：微信小程序端、复杂规则引擎

#### 2. 数据库表字段变更方案

需要包含：

- 现有表哪些保留
- 哪些表新增
- 哪些字段新增
- 哪些字段废弃或兼容保留
- 主外键关系
- 状态字段如何设计

举例：

- 新增 `advisor_reviews` 或在审核记录中增加审核阶段字段
- 新增 `task_source` 区分学生自主申请和学院发布任务
- 新增 `leader_student_id`
- 新增 `material_due_at`

#### 3. 状态流转图

需要画至少 3 条：

- 课时申请状态流转图
- 学分兑换状态流转图
- 申诉状态流转图

举例：

```text
submitted
-> advisor_approved
-> pending_material
-> pending_assignment
-> pending_review
-> pending_admin_final
-> final_approved
```

#### 4. 业务流程图

需要画至少 4 条：

- 学生自主申请流程
- 学分兑换流程
- 申诉流程
- 学院发布任务报名流程

举例：

```text
学生提交申请
-> 指导老师确认
-> 管理员受理
-> 管理员分配审核老师
-> 审核老师审核
-> 管理员最终确认
-> 学生查看结果
```

#### 5. 角色职责表

至少写清楚：

- 学生
- 指导老师
- 审核老师
- 管理员
- 队长/负责人

内容包括：

- 能做什么
- 不能做什么
- 参与哪些流程

#### 6. 接口文档

这里的接口文档在第 1 周不要求写到最终版，但至少要有接口清单草案。

建议先整理：

- 页面路由清单
- 关键表单提交入口
- 管理员批量处理接口
- 导入接口
- 附件上传接口

举例：

- `GET /student/hour-applications/new`
- `POST /student/hour-applications/new`
- `POST /advisor/hour-applications/<id>/approve`
- `POST /admin/credit-exchanges/batch-approve`

#### 7. 页面跳转逻辑（业务层面）

这里需要写的是：

- 哪个角色从哪个页面进入哪个页面
- 提交后跳到哪里
- 驳回后跳到哪里
- 详情页从哪进入

这不是视觉图，而是“业务页面跳转规则”。

举例：

- 学生首页 -> 我的申请 -> 申请详情 -> 补交成果
- 管理员首页 -> 待受理申请 -> 申请详情 -> 分配审核老师

#### 8. 建议补充：页面清单与模块边界

建议你再补 2 项，不然前后端对不齐：

- 页面清单
- 模块边界说明

页面清单回答：

- 这个系统到底有哪些页面

模块边界说明回答：

- 哪些归兑换模块
- 哪些归申诉模块
- 哪些归基础数据模块

#### 9. 建议补充：验收清单

建议在第 1 周就写一个 V1 验收清单初稿。

## 5. 第4周：学分兑换主流程重构

### 5.1 你的工作

#### 1. 规则文件与结构化兑换规则

内容：

- 上传规则文件
- 规则文件只作为制度依据、附件凭证和下载查看材料
- 规则文件入口保持统一，但上传后需要区分 `仅供查阅` 和 `作为结构化兑换规则依据`
- 不做“上传 Word 文档后自动解析规则”
- 新增结构化兑换规则表单
- 学分兑换计算只读取结构化规则，不直接解析规则文件
- 结构化规则与规则文件关联

结构化规则字段建议：

- 规则名称
- 每多少课时兑换 1 学分
- 最大单次兑换课时
- 取整方式：向下取整 / 保留两位 / 四舍五入
- 生效日期
- 失效日期
- 关联规则文件
- 启用/停用状态

明确不做：

- 不做单次最小兑换课时限制
- 不接入大模型自动理解规则文件
- 不把 `.docx` 文件内容直接作为计算依据

建议流程：

```text
管理员上传规则文件
-> 创建规则文件记录
-> 选择文件用途：仅供查阅 / 作为兑换规则依据
-> 管理员填写结构化兑换规则表单
-> 后端保存可执行规则
-> 学生兑换时按结构化规则计算
-> 兑换详情展示关联规则文件作为依据
```

#### 2. 兑换申请重构

内容：

- 个人兑换
- 多人任务队长兑换
- 学分分配逻辑
- 认定证明上传
- 按当前生效的结构化兑换规则计算预计学分

#### 3. 指导老师确认流

内容：

- 兑换申请先到指导老师
- 指导老师通过后再进入管理员端

#### 4. 管理员批量通过

内容：

- 批量审核通过
- 事务一致性
- 批量写入记录

#### 5. 队长分配逻辑

内容：

- 负责人/队长提交分配方案
- 成员学分分配明细

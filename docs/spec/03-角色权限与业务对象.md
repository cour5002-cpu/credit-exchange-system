# 角色权限与业务对象

> 来源：V1需求与设计冻结文档.md。本文档为单一主题拆分稿，开发时优先阅读本文件；总文档保留为全局备份。

### 角色权限与任务限制

#### 1. 学生端

- 提交课时申请
- 补交任务成果
- 申请延期提交成果
- 对于对被驳回的课时申请、被修改课时结果、学分兑换结果发起申诉
- 报名管理员端/指导老师端发布的任务
- 查看课时汇总
- 查看历史任务完成情况
- 选择任务并填写学分兑换申请，同时上传学分对内认定附件
- 查看学分兑换规则
- 查看老师发布的任务

#### 2. 指导老师端

- 确认/驳回学生提交的申请
- 发布任务
- 查看历史申请
- 查看任务状态
- 主指导老师拥有确认、驳回、延期审批等操作权限
- 其他导师仅拥有相关申请和任务的查看权限

#### 3. 审核老师端

- 审核分配到的申请和任务
- 查看历史审核结果

#### 4. 管理员端

- 上传规则文件
- 上传登录身份验证匹配表格
- 确认/驳回学生的任务申请
- 分配审核教师
- 发布任务
- 处理申诉，出具认定书
- 查看历史审核记录、
- 查看历史申诉记录
- 查看投诉信息
- 查看错误日志

### 业务对象

#### 1. 人员与角色类对象

- 用户：系统登录账号。
- 学生：课时申请、任务报名、成果提交、学分兑换、申诉的主要发起人
- 教师：可在不同流程中担任指导老师或审核老师
- 管理员：负责基础数据、任务发布、审核分配、最终确认、申诉处理
- 队长/负责人：学生在多人任务中的特殊身份，负责任务成果提交和学时/学分分配材料提交
- 团队成员：学生在多人任务中的参与身份

#### 2. 申请与处理类对象

- 课时申请：学生申请认定课时的核心单据
- 学分兑换申请：学生将已认定课时兑换为学分的申请单据
- 延期申请：学生因无法按期提交成果而发起的延期请求
- 申诉：学生对被驳回、被修改课时或兑换结果提出异议
- 投诉：学生对流程、人员或结果进行匿名反馈，V1 极简实现，完整处理流程延后
- 导师关联：记录课时申请或任务中的主指导老师和其他导师，导师总人数最多 3 人，只有主指导老师拥有操作权限

#### 3. 任务发布与报名类对象

- 学院任务：由管理员直接发布，或由指导老师发起并经管理员确认后发布的可报名任务
- 任务报名：学生个人报名学院任务的记录
- 任务成员：指导老师筛选后形成的最终参与成员关系
- 任务类别：用于区分不同类型任务及其适用规则
- 任务成果提交：队长代表最终参与成员完成任务后的成果提交记录
- 成果材料：用于证明任务完成情况的材料
- 成员学时/学分分配明细：记录团队任务中每个成员对应的学时、学分分配结果，成员必须与系统用户挂钩

#### 4. 记录与凭证类对象

- 审核记录：记录指导老师、审核老师、管理员的审核动作和意见
- 分配记录：记录管理员将申请分配给审核老师的动作
- 附件记录：记录上传文件及其关联业务对象
- 申诉处理记录：记录管理员对申诉的处理过程和结果
- 课时到账记录：记录最终认定课时的来源和数量
- 学分到账记录：记录最终兑换学分的来源和数量
- 操作日志：记录关键操作，用于追踪和排查问题

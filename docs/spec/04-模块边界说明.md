# 模块边界说明

> 来源：V1需求与设计冻结文档.md。本文档为单一主题拆分稿，开发时优先阅读本文件；总文档保留为全局备份。

### 模块边界说明

#### 1. 用户与权限模块

负责：
- 用户登录、退出
- 区分学生、教师、管理员等身份
- 区分教师在不同流程中的身份：指导老师、审核老师
- 区分主指导老师和其他导师，主指导老师可操作，其他导师仅可查看
- 控制不同角色能访问哪些页面
- 控制不同角色能执行哪些操作
- 控制同一角色在不同状态下能否操作
- 管理学生、教师、管理员基础账号信息

不负责：
- 不负责判断课时申请是否通过
- 不负责判断学分兑换是否通过
- 不负责分配审核老师
- 不负责处理申诉
- 不负责保存成果材料内容

关联对象：
- 用户
- 学生信息
- 教师信息
- 管理员
- 角色
- 权限规则

边界说明：
- 用户与权限模块核心任务：解决谁能登录
- 登录的角色认定
- 用户在权限下的边界，能做什么，不能做什么

#### 2. 课时申请模块

负责：
- 学生提交课时申请
- 支持有成果申请
- 支持无成果申请和后续成果补交
- 支持无成果申请的成果延期申请提交
- 支持多人任务成员填写
- 支持队长/负责人指定
- 支持主指导老师和其他导师设置，导师总人数最多 3 人
- 指导老师确认或驳回课时申请
- 管理员受理课时申请
- 管理员分配审核老师
- 审核老师审核申请材料
- 管理员最终确认
- 生成最终认定课时结果
- 学生查看申请状态和审核结果

不负责：
- 不负责学分兑换
- 不负责学院任务发布
- 不负责任务报名筛选
- 不负责匿名投诉
- 不负责复杂统计报表
- 不负责文件本身的存储实现

关联对象：
- 课时申请
- 课时申请成员
- 成果材料
- 审核记录
- 审核老师分配记录
- 附件记录
- 课时到账记录

边界说明：
- 课时申请模块负责判断“学生是否获得课时”。
- 成果材料的文件保存由附件模块负责，材料是否合格由课时申请审核流程判断
- 通过后的课时可进入学分兑换模块，但兑换结果不反向修改课时申请结论。
- 成果材料可以作为课时申请的证明材料，但文件上传、下载、存储由附件模块负责
- 课时申请最终通过后，结果可以被学分兑换模块使用
- 课时申请模块负责延期申请
- 延期申请仅适用于无成果补交场景
- 每个申请最多延期一次
- 延期由学生发起；普通延期由主指导老师确认；延期超过毕业时长、超过一个学期，或触发学校特殊限制时由管理员审核
- 延期通过后更新成果提交截止时间
- 管理员对所有延期申请具有查看权限
- 学生临近或已经毕业且流程不再具备继续处理条件时，管理员有权终止并关闭流程

#### 3. 学分兑换模块

负责：
- 学生查看可兑换的已认定课时
- 学生选择课时并提交学分兑换申请
- 学生上传学时学分分配证明附件
- 学生填写系统内成员学时/学分分配明细
- 支持多人任务的学分分配明细
- 读取当前生效的结构化兑换规则并计算建议学分
- 保存兑换申请时使用的兑换规则快照
- 指导老师确认或驳回兑换申请
- 管理员确认或驳回兑换申请
- 生成最终学分兑换结果
- 标记相关课时为已兑换或部分兑换
- 学生查看兑换状态和结果

不负责：
- 不重新审核课时申请是否真实
- 不重新判断成果材料是否合格
- 不负责发布学院任务
- 不负责处理课时申请阶段的驳回
- 不负责修改原课时认定结论
- 不负责复杂学分规则引擎
- 不直接解析 Word/PDF 等规则文件中的自然语言内容

关联对象：
- 学分兑换申请
- 学分分配明细
- 成员学时/学分分配明细
- 课时到账记录
- 附件记录
- 审核记录
- 学分到账记录
- 结构化兑换规则

边界说明：
- 学分兑换系统核心任务：已经认定的课时能否兑换为学分，兑换多少学分
- 只能使用已通过并到账的还未使用的课时
- 如果课时申请还没有最终通过，不能进入兑换
- 如果兑换申请被驳回，不影响原课时申请的通过状态
- 学分兑换计算以当前生效的结构化兑换规则为准，规则文件只作为制度依据和附件凭证

#### 4. 任务发布与报名模块

负责：
- 管理员可以直接发布学院任务
- 指导老师可以提交任务发布申请
- 指导老师发布的任务必须经管理员确认后才正式发布
- 管理员未确认前，学生端不可报名
- 任务发布必须设置报名截止时间
- 报名人数不设置上限，截止时间前均可报名
- 学生查看可报名任务
- 学生个人报名任务
- 学生只能个人报名任务，不支持团队报名
- 记录任务成员
- 指定队长/负责人
- 指导老师从个人报名学生中筛选最终参与成员
- 学生查看报名结果
- 报名成功后进入后续成果提交或课时申请流程
- 管理任务类别在任务发布中的使用

不负责：
- 不负责最终认定课时
- 不负责学分兑换
- 不负责课时到账
- 不负责申诉处理
- 不负责匿名投诉
- 不负责审核老师分配

关联对象：
- 学院任务
- 任务报名
- 任务成员
- 任务类别
- 教师信息
- 学生信息
- 课时申请

边界说明：
- 任务发布与报名模块核心任务：学校发布了什么任务，哪些学生个人报名并被选中
- 任务报名成功不等于课时到账
- 学生完成任务后需要提交任务成果，并进入课时申请认定流程
- 课时是否通过，由课时申请模块负责

#### 5. 申诉模块

负责：
- 学生对被驳回的课时申请发起申诉
- 学生对被修改课时结果发起申诉
- 学生对学分兑换被驳回或被修改结果发起申诉
- 限制同一业务对象的申诉次数
- 管理员查看申诉详情
- 管理员处理申诉
- 管理员填写申诉处理意见
- 记录申诉处理结果
- 学生查看申诉结果

不负责：
- 不替代正常审核流程
- 不直接完成课时到账
- 不直接完成学分到账
- 不处理匿名投诉
- 不处理普通问题反馈
- 不修改与申诉无关的申请

关联对象：
- 申诉
- 申诉处理记录
- 课时申请
- 学分兑换申请
- 审核记录
- 附件记录
- 管理员

边界说明：
- 申诉模块核心任务：学生对已有处理结果提出异议后，管理员是否接受这个异议
- 申诉通过不等于自动通过原申请
- 申诉通过后，原业务进入重新提交或重新审核状态

#### 6. 附件与基础数据模块

负责：
- 附件上传
- 附件下载
- 附件删除或作废
- 记录附件归属的业务对象
- 限制附件类型、大小、数量
- 上传规则文件
- 维护规则文件的标题、说明、类型、版本和启停状态
- 管理任务类别
- 导入学生名单
- 导入教师名单
- 导入管理员名单
- 维护基础身份数据

不负责：
- 不判断成果材料是否合格
- 不判断课时申请是否通过
- 不判断学分兑换是否通过
- 不计算课时可兑换多少学分
- 不从规则文件中自动解析可执行兑换公式
- 不处理申诉结论
- 不决定谁是审核老师
- 不负责业务状态流转

关联对象：
- 附件记录
- 规则文件
- 任务类别
- 用户
- 学生信息
- 教师信息
- 管理员信息

边界说明：
- 附件与基础数据模块基本任务：
    - 文件怎么存
    - 文件属于哪个业务
    - 基础人员数据从哪里来
    - 任务类别怎么维护
- 规则文件可以只是供师生查阅的制度文件，也可以被结构化兑换规则关联作为制度依据
- 该模块不决定任何业务是否通过

#### 7. 投诉模块：完整实现 V1 延后

- V1 极简实现：学生匿名投诉，管理员查看投诉信息，不做处理流转。
- 未来可扩展为：匿名投诉提交、附件（是否只查看）

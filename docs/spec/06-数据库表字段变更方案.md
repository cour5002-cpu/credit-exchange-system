# 数据库表字段变更方案



> V1 范围说明：数据统计、统计报表、统计卡片、统计图、首页数量概览、首页工作台概览均统一延后实现，不设计统计汇总表；成绩统计模块未来独立设计，不混入本数据库方案。
> 本文档复制自 V1需求与设计冻结文档.md 的“数据库表字段变更方案”章节。

说明：
- 本节基于当前已有 14 张旧表进行 V1 数据库变更设计。
- 现有 14 张旧表仍按“旧表 - 修改说明 - 新表”的格式保留。
- “删除”不代表业务信息不要了；如果该信息仍是 V1 必需信息，会在修改说明中标明迁移到哪张新表或哪个新字段。
- V1 统一采用 `task_type_id` 关联任务类别。
- V1 统一采用 `reviewer_reviewed_at` 表示审核老师审核时间。
- V1 保留 `achievement_summary` 作为成果说明字段，说明为“对成果内容、完成情况、证明材料的文字概述”
- 表数量口径：V1 业务相关表共 28 张；如果加上数据库迁移版本表 `alembic_version`，物理数据库表共 29 张。

数据库文档使用说明：
- 本文档是 V1 数据库稳定设计依据，覆盖 V1 范围内计划使用的表、字段、主外键关系、兼容策略和状态枚举。
- 本文档不维护每日迁移进度；每天实际新增了哪些字段、执行了哪些迁移、验证结果如何，记录在 `docs/development/weekX/dayY-backend.md`。
- 只有数据库契约发生变化时才修改本文档，例如新增表、删除表、字段类型或必填约束变化、主外键关系变化、状态枚举变化。
- 文档中的“兼容保留”表示旧字段物理上可以继续存在，但 V1 新功能不依赖它作为核心业务字段。
- 如果发现本文档与模型或迁移不一致，先判断是“实现偏离数据库设计”还是“数据库设计需要变更”；不确定时必须先确认再改。

##### 1.2 users 用户表

用途：
- 保存系统登录账号、登录角色和基础联系方式

旧表：
| 字段名 | 类型 | 约束/说明 |
|---|---|---|
| id | BigInteger | 主键 |
| username | String(64) | 唯一，必填 |
| password_hash | String(255) | 必填，密码哈希 |
| role | String(20) | 必填，系统角色 |
| real_name | String(64) | 必填，真实姓名 |
| phone | String(32) | 可空 |
| email | String(128) | 可空 |
| status | String(20) | 必填，默认 active |
| last_login_at | DateTime | 可空，最后登录时间 |
| created_at | DateTime | 必填，创建时间 |
| updated_at | DateTime | 必填，更新时间 |

修改说明：
- `phone` 当前数据库仍保持可空；V1 可在导入模板和业务校验层提示填写，但本阶段不通过迁移改成非空。
- 不删除其他字段

新表：
| 字段名 | 类型 | 必填 | 说明 |
|---|---|---|---|
| id | BigInteger | 是 | 主键 |
| username | String(64) | 是 | 登录账号，唯一 |
| password_hash | String(255) | 是 | 密码哈希 |
| role | String(20) | 是 | student / teacher / advisor / reviewer / admin；教师多能力以 teachers.role_flags 为准 |
| real_name | String(64) | 是 | 真实姓名 |
| phone | String(32) | 否 | 手机号；当前数据库可空 |
| email | String(128) | 否 | 邮箱 |
| status | String(20) | 是 | active / disabled |
| last_login_at | DateTime | 否 | 最后登录时间，首次登录前为空 |
| created_at | DateTime | 是 | 创建时间 |
| updated_at | DateTime | 是 | 更新时间 |

设计说明：
- `last_login_at` 保持可空，首次登录前没有最后登录时间
- 登录保持由 Flask-Login session/cookie 控制；API 接口使用 session cookie，不使用 Authorization token。

##### 3.12.1 credit_conversion_rules 结构化学分兑换规则表

用途：
- 保存真正参与课时兑换学分计算的结构化规则。
- 规则文件只作为制度依据和下载材料，后端不直接解析规则文件自然语言内容。

| 字段名 | 类型 | 必填 | 说明 |
|---|---|---|---|
| id | BigInteger | 是 | 主键 |
| rule_name | String(128) | 是 | 规则名称，例如“默认课时兑换规则” |
| hours_per_credit | Numeric(10,2) | 是 | 每多少课时兑换 1 学分，例如 10 |
| max_single_exchange_hours | Numeric(10,2) | 是 | 最大单次兑换课时，例如 100 |
| rounding_mode | String(32) | 是 | floor / keep_2 / round_half_up；向下取整 / 保留两位 / 四舍五入 |
| effective_at | DateTime | 是 | 生效时间 |
| expires_at | DateTime | 是 | 失效时间，到期后不再作为当前有效规则 |
| rule_file_id | BigInteger | 是 | 外键，关联 rule_files.id，作为制度依据 |
| status | String(20) | 是 | active / inactive |
| created_by | BigInteger | 是 | 外键，关联 users.id，创建管理员 |
| created_at | DateTime | 是 | 创建时间 |
| updated_at | DateTime | 是 | 更新时间 |

约束与规则：
- 不设置最小单次兑换课时限制。
- 单次兑换课时不得超过 `max_single_exchange_hours`。
- 当前有效规则必须满足 `status = active` 且 `effective_at <= now < expires_at`。
- 同一时间不允许存在多条时间区间重叠的 active 兑换规则，避免兑换计算歧义。
- 创建或修改兑换申请时，应将本次使用的规则写入兑换申请或兑换结果的 `rule_snapshot`。

# 状态流转

> 本文档复制自 V1需求与设计冻结文档.md 的“状态流转”章节。

说明：
- 本节按 7 条业务主线分别展开状态流转，方便检查每条主线是否闭环。
- 后续数据库设计时，相同阶段可归并到同一张表和同一套状态字段中。
- 管理员前段“受理”仅表示分配审核老师，不作为业务审核结论；管理员业务审核只发生在最终确认阶段。
- 指导老师驳回不进入申诉流程，学生应修改后重新提交或关闭申请。
- 状态名暂定为英文小写下划线格式，后续开发时可根据代码规范微调。
- 所有时间以 `Asia/Shanghai` 后端时间为准；任务在 `now >= registration_deadline` 时自然截止并直接进入 `selection_pending`。
- `registration_closed` 仅作为历史数据兼容状态保留，不作为 V1 自然截止时必须落库的中间阶段。

#### 1. 学生课时申请（有成果版）状态流转

主流程：

```text
submitted
-> advisor_approved
-> pending_assignment
-> pending_review
-> reviewer_approved / reviewer_modified_approved
-> pending_admin_final
-> final_approved
```

| 状态 | 业务对象/落表字段 | 中文含义 | 触发动作 | 操作角色 | 下一个状态 | 是否终态 | 是否可申诉 | 备注 |
|---|---|---|---|---|---|---|---|---|
| draft | hour_applications.status | 草稿 | 保存申请草稿 | 学生 | submitted / discarded | 否 | 否 | 草稿仅自己可见 |
| submitted | hour_applications.status | 已提交，待主指导老师确认 | 学生提交有成果课时申请 | 学生 | advisor_approved / advisor_rejected | 否 | 否 | 学生必须选择主指导老师，可选其他查看导师 |
| advisor_approved | hour_applications.status | 主指导老师已确认 | 主指导老师确认通过 | 主指导老师 | pending_assignment | 否 | 否 | 进入管理员分配审核老师环节 |
| advisor_rejected | hour_applications.status | 主指导老师已驳回 | 主指导老师驳回 | 主指导老师 | submitted / closed | 否 | 否 | 学生修改后可重新提交；不进入申诉流程 |
| pending_assignment | hour_applications.status | 待管理员分配审核老师 | 主指导老师确认通过 | 系统 | pending_review | 否 | 否 | 管理员在此只做分配审核老师，不做业务审核结论 |
| pending_review | hour_applications.status | 待审核老师审核 | 管理员分配审核老师 | 管理员 | reviewer_approved / reviewer_modified_approved / reviewer_rejected | 否 | 否 | 只有被分配的审核老师可审核 |
| reviewer_approved | hour_applications.status | 审核老师已通过 | 审核老师审核通过，且未修改课时 | 审核老师 | pending_admin_final | 否 | 否 | 申请课时与审核认定课时一致 |
| reviewer_modified_approved | hour_applications.status | 审核老师已修改并通过 | 审核老师审核通过，但修改认定课时 | 审核老师 | pending_admin_final | 否 | 是 | 学生可对被修改课时结果发起申诉，最终仍需管理员确认 |
| reviewer_rejected | hour_applications.status | 审核老师已驳回 | 审核老师驳回申请 | 审核老师 | submitted / appealed / closed | 否 | 是 | 退回学生端，指导老师仅历史可见 |
| pending_admin_final | hour_applications.status | 待管理员最终确认 | 审核老师审核通过后进入 | 系统 | final_approved / final_rejected | 否 | 否 | 管理员确认审核老师结论，包括修改后的课时 |
| final_approved | hour_applications.status / hour_award_records | 最终通过，课时到账 | 管理员最终确认通过 | 管理员 | 无 | 是 | 否 | 生成课时到账记录，不可重复确认 |
| final_rejected | hour_applications.status | 最终驳回 | 管理员最终驳回 | 管理员 | appealed / closed | 是 | 是 | 对课时申请流程来说是终态，但可进入申诉流程 |
| appealed | hour_applications.status / appeals.status | 已发起申诉 | 学生发起申诉 | 学生 | 进入申诉流程 | 否 | 否 | 当前申请进入申诉处理，不再按普通审核流程推进 |
| discarded | hour_applications.status | 草稿已删除 | 学生删除或放弃草稿 | 学生 | 无 | 是 | 否 | 草稿未进入正式流程，仅删除草稿记录 |
| closed | hour_applications.status | 已关闭 | 学生放弃/系统关闭/申诉结束关闭 | 学生/系统/管理员 | 无 | 是 | 否 | 仅保留历史记录 |

#### 2. 学生课时申请（无成果，补交版）状态流转

主流程：

```text
submitted
-> advisor_approved
-> pending_material
-> material_submitted
-> advisor_approved
-> pending_assignment
-> pending_review
-> pending_admin_final
-> final_approved
```

| 状态 | 业务对象/落表字段 | 中文含义 | 触发动作 | 操作角色 | 下一个状态 | 是否终态 | 是否可申诉 | 备注 |

| draft | hour_applications.status | 草稿 | 保存申请草稿 | 学生 | submitted / discarded | 否 | 否 | 草稿仅自己可见 |

| advisor_approved | hour_applications.status | 主指导老师已确认 | 主指导老师确认通过 | 主指导老师 | pending_material / pending_assignment | 否 | 否 | 首次确认后进入待补交成果；补交成果后再次确认则进入分配审核老师 |
| advisor_rejected | hour_applications.status | 主指导老师已驳回 | 主指导老师驳回 | 主指导老师 | submitted / closed | 否 | 否 | 学生修改后可重新提交；不进入申诉流程 |

| pending_assignment | hour_applications.status | 待管理员分配审核老师 | 主指导老师确认补交成果通过 | 系统 | pending_review | 否 | 否 | 管理员在此只做分配审核老师 |
| pending_review | hour_applications.status | 待审核老师审核 | 管理员分配审核老师 | 管理员 | reviewer_approved / reviewer_modified_approved / reviewer_rejected | 否 | 否 | 只有被分配的审核老师可审核 |
| reviewer_approved | hour_applications.status | 审核老师已通过 | 审核老师审核通过，且未修改课时 | 审核老师 | pending_admin_final | 否 | 否 | 申请课时与审核认定课时一致 |

#### 3. 管理员端发布任务状态流转

说明：
- 本主线包含任务发布、任务报名、成果提交后进入课时认定。
- 成果提交后的课时认定阶段复用课时申请后半段状态。

| published | college_tasks.status | 任务已发布 | 管理员发布任务 | 管理员 | registration_open / selection_pending | 否 | 否 | 管理员发布后学生端可见 |
| registration_open | college_tasks.status | 报名中 | 发布后进入报名阶段 | 系统/管理员 | selection_pending | 否 | 否 | 报名截止前学生均可报名 |

#### 6. 申诉状态流转

说明：
- 申诉通过不等于课时或学分自动到账
- 申诉通过只表示管理员接受异议，原业务重新打开，并按原课时申请流程进入：指导老师再次确认 -> 管理员再次分配审核老师 -> 审核老师复审 -> 管理员最终确认

| 状态 | 业务对象/落表字段 | 中文含义 | 触发动作 | 操作角色 | 下一个状态 | 是否终态 | 是否可再次申诉 | 备注 |
|---|---|---|---|---|---|---|---|---|
| submitted | appeals.status | 已提交申诉 | 学生提交申诉 | 学生 | pending_admin_review | 否 | 否 | 同一业务对象只能申诉一次 |
| pending_admin_review | appeals.status | 待管理员处理 | 申诉进入管理员端 | 系统 | appeal_accepted / appeal_rejected | 否 | 否 | 管理员查看材料并填写处理意见 |
| appeal_accepted | appeals.status | 申诉通过 | 管理员通过申诉 | 管理员 | original_reopened | 是 | 否 | 申诉流程结束，原业务进入指导老师再次确认环节 |
| appeal_rejected | appeals.status | 申诉驳回 | 管理员驳回申诉 | 管理员 | closed | 是 | 否 | 原结果维持，申诉入口关闭 |
| original_reopened | appeals.status | 原业务已重新打开 | 系统重开原课时申请或兑换申请 | 系统 | 无 | 是 | 否 | 对申诉流程来说是终态；原业务后续按“指导老师再次确认 -> 管理员再次分配审核老师 -> 审核老师复审 -> 管理员最终确认”流转 |
| closed | appeals.status | 已关闭 | 申诉处理完成并关闭 | 系统/管理员 | 无 | 是 | 否 | 仅保留历史记录 |

#### 7. 投诉状态流转

说明：
- V1 极简实现：学生匿名投诉，管理员查看投诉信息，不做处理流转。
- 完整投诉处理流程延后。

| 状态 | 业务对象/落表字段 | 中文含义 | 触发动作 | 操作角色 | 下一个状态 | 是否终态 | 是否可申诉 | 备注 |
|---|---|---|---|---|---|---|---|---|

| viewed | complaints.status | 管理员已查看 | 管理员查看投诉 | 管理员 | 无 | 是 | 否 | V1 不做处理、回复、关闭流转 |

#### 状态复用说明

- 学生课时申请、任务成果认定后续都可以落到课时申请模块
- 管理员端发布任务和指导老师端发布任务后续都可以落到任务发布与报名模块
- 任务报名可以独立维护报名状态，进入课时认定后切换到课时申请状态
- 学分兑换、申诉、投诉分别独立维护状态
- 文档阶段按主线展开，数据库设计阶段可以根据表结构合并相同状态字段

# V1 规格文档索引

开发时优先阅读单体文档，`01-V1范围与设计冻结.md` 保留为总文档和历史备份。

## 文档维护规则

- `docs/spec/` 是稳定设计依据，包含 V1 范围、流程、状态、权限、数据库、接口、页面触发关系和验收标准。
- `docs/spec/07-V1接口文档.md` 是前后端分离 API 契约，必须覆盖 V1 计划提供的全部 `/api/v1` 接口；接口路径、方法、参数、响应、权限、错误码和业务规则以它为准。
- `docs/spec/06-数据库表字段变更方案.md` 是数据库契约，必须覆盖 V1 计划使用的表、字段、关系和兼容策略。
- `docs/spec/` 不记录每日实现进度；每天实现了哪些接口、执行了哪些迁移、测试了什么、遇到什么问题，记录在 `docs/development/weekX/dayY-backend.md`。
- 只有设计契约变化时才修改 `docs/spec/`；单纯实现进度变化只修改开发记录。
- 如果文档、代码、测试结果之间出现不一致，必须记录问题、原因和解决方案；不确定的业务口径必须先确认再修改。

# V1验收标准

> 来源：V1需求与设计冻结文档.md。本文档为单一主题拆分稿，开发时优先阅读本文件；总文档保留为全局备份。

### 验收标准

#### 用户与权限验收

- 学生、指导老师、审核老师、管理员可以使用各自账号登录系统
- 前后端分离登录页可以通过 `POST /api/v1/auth/login` 完成登录
- 登录成功后，前端可以通过 `GET /api/v1/me` 获取当前用户角色和身份信息
- 用户可以通过 `POST /api/v1/auth/logout` 退出登录
- 退出登录后，再访问受保护接口应返回未登录
- 不同角色登录后进入对应首页
- 学生不能访问指导老师、审核老师、管理员页面
- 指导老师不能访问管理员专属操作页面
- 审核老师只能查看和处理分配给自己的审核任务
- 管理员可以访问管理端功能，但不能绕过流程直接替学生完成申请
- 未登录用户不能访问系统内部页面
- 已停用账号不能登录系统

#### 课时申请主线验收

- 学生可以提交有成果的课时申请
- 学生可以提交无成果的课时申请，并填写成果提交时间
- 学生提交课时申请时必须选择主指导老师
- 学生可选择其他导师作为查看角色，导师总人数最多 3 人
- 只有主指导老师可以确认、驳回课时申请，其他导师仅可查看
- 无成果申请在补交成果前不能进入管理员分配审核环节
- 无成果申请的预计成果提交时间必须在系统允许时限内
- 学生可以在规定时间内补交成果材料
- 学生可以申请延期补交材料，延期申请仅一次
- 普通延期申请提交后，需要主指导老师确认
- 延期超过毕业时长、超过一个学期，或触发学校特殊限制时，需要管理员审核
- 管理员可以查看所有延期申请
- 学生临近或已经毕业且流程不再具备继续处理条件时，管理员可以终止并关闭流程
- 补交成果后，需要指导老师再次确认
- 指导老师可以确认或驳回学生课时申请
- 指导老师驳回后，申请退回学生端
- 管理员可以受理指导老师确认后的申请
- 管理员可以为申请分配审核老师
- 未分配审核老师的申请不能进入审核老师审核环节
- 审核老师可以审核分配给自己的申请
- 审核老师不能审核未分配给自己的申请
- 审核老师审核通过后，申请进入管理员最终确认环节
- 管理员最终确认通过后，课时到账
- 管理员最终驳回后，申请退回学生端并记录原因
- 学生可以查看申请当前状态、审核意见和最终结果

#### 多人参与与队长验收

- 指导老师筛选多个参与学生后，必须指定一名队长/负责人
- 若最终仅 1 名学生参与，则该学生默认为队长
- 队长必须属于最终参与成员之一
- 同一个任务只能有一名队长
- 系统可以记录每个成员的信息，成员必须与系统用户挂钩
- 任务审核通过后，可以明确每个成员获得的课时或参与结果
- 成员信息不完整时，申请不能提交
- 队长信息缺失时，申请不能提交

#### 任务发布与报名验收

- 管理员可以发布学院任务
- 指导老师可以发起任务发布申请
- 指导老师发布任务时必须填写报名截止时间
- 管理员可以确认或驳回指导老师发布的任务
- 管理员确认后，该任务才对学生可见并可报名
- 管理员驳回后，指导老师可以查看驳回原因
- 学生可以查看已发布且可报名的任务
- 学生只能个人报名任务，不支持团队报名
- 指导老师筛选最终参与学生后，必须指定队长/负责人
- 任务报名不设置报名人数上限，在报名截止时间前学生均可报名
- 报名截止后，学生不能继续报名
- 指导老师可以从个人报名学生中筛选最终参与成员
- 被选中的学生在指定队长后可以继续提交成果
- 未被选中的学生不能进入成果提交和课时认定流程
- 学生可以查看自己的报名状态
- 任务报名成功不等于课时到账，仍需进入后续课时认定流程

#### 学分兑换验收

- 学生只能选择已最终确认到账的课时发起学分兑换
- 未到账、被驳回、已撤回的课时不能用于兑换
- 已兑换的课时不能重复兑换
- 学生可以提交学分兑换申请
- 学生申请兑换学分时必须上传学时学分分配证明附件
- 学生申请兑换学分时必须填写系统内成员学时/学分分配明细
- 学生发起兑换申请时，系统必须按当前生效的结构化兑换规则计算建议学分
- 当前没有生效结构化兑换规则时，学生不能提交兑换申请
- 单次兑换课时不能超过当前生效结构化兑换规则的最大单次兑换课时
- 系统不设置最小单次兑换课时限制
- 每个成员可以查看自己对应的学时/学分分配结果
- 指导老师可以确认或驳回兑换申请
- 管理员可以最终确认或驳回兑换申请
- 管理员确认通过后，学分到账
- 兑换被驳回后，不影响原课时到账记录
- 学生可以查看兑换申请状态和结果

#### 申诉验收

- 学生可以对被驳回的课时申请发起申诉
- 学生可以对被修改课时结果的申请发起申诉
- 学生可以对学分兑换被驳回或被修改结果发起申诉
- 同一个业务对象只能发起一次申诉
- 已经申诉过且处理完成的对象不能重复申诉
- 管理员可以查看申诉详情
- 管理员可以填写申诉处理意见
- 管理员可以通过或驳回申诉
- 申诉通过后，原业务进入重新提交或重新审核状态
- 申诉驳回后，学生可以查看驳回原因
- 申诉不会绕过原有审核流程直接完成课时或学分到账

#### 附件与基础数据验收

- 学生可以上传课时申请所需成果材料
- 学生可以上传学分兑换所需认定附件
- 管理员可以上传规则文件
- 管理员可以把规则文件标记为仅供查阅或结构化兑换规则依据
- 仅供查阅的规则文件只能用于查看、下载和留痕，不能参与学分兑换计算
- 管理员可以基于规则文件创建结构化兑换规则
- 结构化兑换规则必须包含规则名称、每学分所需课时、最大单次兑换课时、取整方式、生效时间、失效时间和关联规则文件
- 到达失效时间后，结构化兑换规则不能继续作为当前生效规则使用
- 系统不从 Word/PDF 等规则文件中自动解析兑换公式
- 系统可以限制附件类型
- 系统可以限制附件大小
- 系统可以记录附件所属业务对象
- 没有关联业务对象的附件不能作为有效材料使用
- 有权限的用户可以下载自己有权查看的附件
- 无权限用户不能下载他人或其他角色专属附件
- 管理员可以导入学生名单
- 管理员可以导入教师名单
- 管理员可以维护任务类别
- 被停用的任务类别不能用于新申请或新任务发布

#### 数据一致性验收

- 每次审核动作都必须生成审核记录
- 每次管理员分配审核老师都必须生成分配记录
- 申请状态变化必须符合状态流转规则
- 终态申请不能被普通用户继续修改
- 课时到账后，学生课时汇总能正确显示
- 学分到账后，学生学分兑换记录能正确显示
- 同一申请不能因为重复点击产生重复审核记录或重复到账
- 被驳回的申请不会出现在可兑换课时列表
- 已兑换课时不会再次出现在可兑换列表
- 删除或作废附件后，业务详情中不能继续显示为有效材料

#### 异常与边界验收

- 必填字段缺失时，表单不能提交
- 主指导老师未选择时，课时申请不能提交
- 成果提交时间缺失时，无成果申请不能提交
- 附件不符合类型或大小限制时，不能上传成功
- 当前状态不允许的操作不能执行
- 重复提交、重复审核、重复确认时，系统不能产生重复结果
- 用户直接访问无权限链接时，系统应拒绝访问
- 查询不存在的数据时，系统应给出明确提示
- 操作失败时，系统应保留原数据状态，不产生半完成数据
